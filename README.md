# Clavier Unibody 64keys ZMK Firmware

左右一体型・トラックボール無し・IOエクスパンダー(MCP23017)搭載のカスタムキーボード用ZMKファームウェアです。
[claudecode_clavier](https://github.com/yuidayo848/claudecode_clavier)（左右分割・トラックボール付き機）から派生しています。

## ハードウェア構成

| 項目 | 内容 |
|------|------|
| マイコン | Seeed Studio XIAO nRF52840（1個、左右一体） |
| IOエクスパンダー | MCP23017（I2C、アドレス固定 0x20） |
| キー数 | 68キー（5行 × 最大16列、うち親指クラスタ4キー） |
| トラックボール | 無し |
| 接続方式 | BLE無線 + USB |

回路図・基板データ（`Unibody_64keys.kicad_sch` / `.kicad_pcb`）から実測した配線に基づいてファームウェアを作成しています。

## ピンアサイン

### マイコン (XIAO nRF52840)

| 信号 | XIAO端子 | nRF52840 GPIO |
|------|----------|---------------|
| Col0 | A2 | P0.02 |
| Col1 | A4 | P0.03 |
| Col2 | A10 | P0.28 |
| Col3 | A11 | P0.29 |
| Col4 | A8_SDA | P0.04 |
| Col5 | A9_SCL | P0.05 |
| Col6 | B8_TX | P1.11 |
| Col7 | A7_SCK | P1.13 |
| I2C SCL | A5_MISO | P1.14 |
| I2C SDA | A6_MOSI | P1.15 |
| MCP_INT (未使用) | B9_RX | P1.12 |

> 基板シルク印刷上「SDA/SCL」と書かれているP0.04/P0.05ピンは、実際の回路図ではCol4/Col5として使われており、I2Cバスは別のピン(P1.14/P1.15)に配線されています。ファームウェアはこの実配線に合わせています。

### MCP23017 (I2Cアドレス 0x20)

| ピン | 信号名 | 機能 |
|------|--------|------|
| 21,22,23 | GPA0,GPA1,GPA2 | Col8, Col9, Col10 |
| 24,25,26,27,28 | GPA3,GPA4,GPA5,GPA6,GPA7 | Row4, Row3, Row2, Row1, Row0 |
| 1,2,3,4,5 | GPB0-4 | Col11, Col12, Col13, Col14, Col15 |
| 6,7,8 | GPB5,GPB6,GPB7 | 未使用（予備） |
| 20 | INTA | MCP_INT（本ファームウェアでは未使用、ポーリング方式のため） |

## ⚠ 既知の制約・注意点

### 1. MCP23017 GPA7ピンのエラッタについて【本基板では問題無し】

Row0が接続されているMCP23017の **GPA7** ピンについては、Microchipのエラッタで「ロットによっては出力専用・入力として使用不可」との報告がある（[Microchip公式Errata](https://microchip.my.site.com/s/article/GPA7---GPB7-Cannot-Be-Used-as-Inputs-In-MCP23017)）。本基板の実機では**Row0（最上段16キー）も含めて問題なく動作することを確認済み**。万一別の個体で発生した場合は、空いているGPB5（物理ピン6）またはGPB6（物理ピン7）へRow0の配線をジャンパー線で引き直し、`clavier_unibody.overlay` の `row-gpios` 1行目を該当ピンに変更すること。

### 2. 【解決済み】MCP23017側のRow線にプルダウン抵抗が無い問題

MCP23017は内蔵プルアップ抵抗のみ対応しており、プルダウンには対応していません（Zephyrのドライバも `GPIO_PULL_DOWN` 指定を明示的にエラーとして拒否します）。そのためRow0〜4（全てMCP23017側）が実際にフローティング（浮いた状態）になり、1キー押下で無関係なキーまで誤反応する・押しっぱなしで入力が止まらない、といった深刻な誤動作が発生した。

**対応: 基板改修で解決済み（2026-09-19）。** Row0〜Row4それぞれについて、そのRowに繋がるダイオードのカソード側の足（例: Row0=D9, Row1=D17, Row2=D33, Row3=D49, Row4=D65）とGND（XIAOの13番ピン）の間に、10kΩのプルダウン抵抗を1本ずつ空中配線で追加した。これにより本来の標準的なZMKキースキャン処理（本リポジトリの現在のファームウェア）で正常動作することを確認済み。

この改修を行っていない基板では、標準のファームウェアのままだと同様の誤動作が発生する。

> ⚠ プルダウン抵抗の改修後、**全く同じファームウェアで「動く/動かない」が再現性なく入れ替わる**現象が発生したことがある。原因はファームウェアではなく、5本の抵抗のGND側をまとめた接続点（13番ピン等）の接触不良と推定される。もし今後同様の「急に全キー無反応になる」症状が出た場合、ファームウェアを疑う前に、まずこの接続点(および各抵抗のハンダ付け箇所)の導通をテスターで確認すること。

### 3. 未接続のコネクタ J2〜J15

回路図上に14個の未接続1ピンコネクタ(`Conn_01x01`)があります（テストポイント等と思われますが念のため）。ファームウェア上は無視して問題ありません。

## キースキャン方式

- MCP23017経由のGPIOはマイコンのGPIO割り込み(GPIOTE)を使えないため、`CONFIG_ZMK_KSCAN_MATRIX_POLLING=y` による定期ポーリング方式（10ms間隔）でスキャンしています。

## ビルド・フラッシュ方法

元のリポジトリと同様、GitHub Actionsで自動ビルドされます。

1. このリポジトリへpush
2. Actionsタブ → 完了したワークフロー → Artifactsから `clavier_unibody-seeeduino_xiao_ble` をダウンロード
3. XIAO nRF52840のリセットボタンを**素早く2回押す**とブートローダーモードになり、`XIAO-SENSE`ドライブが表示される
4. `.uf2`ファイルをドライブにコピー

初回ペアリングで接続できない場合は `settings_reset` ファームウェア（`build.yaml`に含まれています）を書き込んでから通常ファームウェアを書き込んでください。

## ZMKキーマップ編集アプリでの設定方法

このリポジトリは、[claudecode_clavier](https://github.com/yuidayo848/claudecode_clavier)向けに作成したZMKキーマップ編集アプリ（Electronアプリ）で**そのまま**編集できます。アプリ自体の改造は不要です。

初回セットアップ画面で以下のように入力してください（「ファイル構造を自動検出する」でキーマップ/レイアウトJSONは自動検出されますが、オーバーレイ/設定ファイルは名前が`_left`で終わっていないため自動検出されません。手動で入力してください）:

| 項目 | 値 |
|------|-----|
| キーマップファイル | `config/clavier_unibody.keymap` |
| レイアウトJSON | `config/clavier.json` |
| 左側オーバーレイ | `config/boards/shields/clavier_unibody/clavier_unibody.overlay` |
| 左側設定 | `config/boards/shields/clavier_unibody/clavier_unibody.conf` |
| ボード名 | `seeeduino_xiao_ble` |

> 「左側オーバーレイ/左側設定」という項目名はアプリが分割キーボード向けに付けた名前ですが、実体はこの一体型キーボードの唯一のオーバーレイ/設定ファイルを指すだけで問題なく動作します。
> アプリ内の「トラックボール」タブは本キーボードには無関係なので無視してください（設定してもファームウェアには反映されません）。

## 物理レイアウト（レイアウトJSON）について

`config/clavier.json` の各キーのX/Y座標は、KiCad基板データ(`Unibody_64keys.kicad_pcb`)から実測したスイッチ中心座標を、16mm=1グリッド単位としてスケーリングしたものです。

キーマップ編集アプリは現状**回転角度(rotation)の表示に対応していない**ため、実際の基板は外周キーが±15°〜35°傾いたカーブレイアウトですが、アプリ上ではその傾きは反映されず、位置(X/Y)のみでの近似表示になります（アプリ自体の改造は行わない方針のため）。

## デフォルトレイヤーについて

`config/clavier_unibody.keymap` に入っているキー配列は、動作確認用の暫定的なQWERTYベース配列です。実際のキー割り当ては、ZMKキーマップ編集アプリのGUI上で自由に変更してください。
